| 19 | 2026-06-22 | S0-v2 egress gateway uses REDIRECT in nat PREROUTING (not TPROXY) for cross-container transparent proxying | TPROXY requires policy routing (`ip rule add fwmark`), specific kernel modules, and exact `rp_filter` configurations that Docker Desktop overrides/strips. Packets were dropped by routing before hitting mangle chain rules. REDIRECT in nat PREROUTING alters destination IP to gateway's own IP; conntrack handles reverse-NAT for responses; `SO_ORIGINAL_DST` recovers original destination. Single-container mode (OUTPUT REDIRECT) proven working on Docker Desktop. Cross-container gateway mode (PREROUTING REDIRECT) implemented but unproven on Docker Desktop due to conntrack limitations across Docker network namespaces; would work on real Linux hosts / Kubernetes. Proxy supports both modes: `--no-tproxy` forces REDIRECT, TPROXY available for production Linux hosts | (a) TPROXY in mangle PREROUTING (rejected — Docker Desktop lacks policy routing); (b) REDIRECT in nat PREROUTING (selected — works with conntrack); (c) app-layer proxy without iptables (rejected — shell tools bypass it) | active |
